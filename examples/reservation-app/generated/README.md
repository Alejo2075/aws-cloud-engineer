# booking-app

Generated by [Cloud Engineer](https://github.com/Alejo2075/aws-cloud-engineer).
HTTP API (API Gateway) + Lambda + DynamoDB, with Cognito JWT authentication on every route. API only:
there is no web page; call the API with a Cognito ID token (`Authorization: Bearer <token>`).

## Entities

- **Booking** (`/bookings`): `guestName` (string, required), `partySize` (number, required), `date` (string, required)

Each entity exposes `GET/POST /<name>s` and `GET/PUT/DELETE /<name>s/{id}` (PUT replaces the declared fields; `id` and `createdAt` are kept). Items are scoped to the
authenticated Cognito user (`sub`).

## Commands

```bash
npm install
npm run typecheck && npm test   # unit + infrastructure assertions
npm run synth                   # build the Lambda bundle and synthesize the template
npm run deploy                  # deploys to your AWS account; review `cdk diff` first
```

Stage defaults to `staging`; use `npx cdk deploy -c stage=production` for production
(data and the user pool are retained on stack deletion in production only).

## Known limitations

- Sign-up uses Cognito's email code flow, so the user pool needs working email delivery (Cognito's default
  sender has a low daily limit).
- The API sends no CORS headers, so browsers on another origin cannot call it directly.
- Listings are paginated (`limit` 1-100, default 50, opaque `nextCursor`).
